# 04 · 与独弈 0.3 中继的对应（草案 0）

独弈 0.3 的联机靠独弈仓库里的 `services/netplay-relay/relay.mjs`：裸 TCP、JSON Lines、第一行是请求，配对后变成透明管子。
Tablenet 节点是它的继任者。本篇写清楚怎么一一对应，以及老客户端怎么继续能用。

## 动作对照

| 0.3 中继 | tablenet/1 | 备注 |
|---|---|---|
| `relay_ping` → `relay_pong` | `ping` / `pong`；测速另用 `node.hello` 往返时间 | |
| `relay_host` → `relay_hosting` | `room.open` → `room.opened` | 元数据字段名对照见下 |
| `relay_host` 带 `spectate:true`（观战门） | 不需要了：同一条连接上开多条对局通道，观战者和断线回来的人都走 `room.join` | |
| `relay_join` → `relay_paired` | `room.join` → `room.joined` + 对局通道 | 管子从「整条 TCP」变成「一条逻辑通道」 |
| `relay_list` → `relay_rooms` | `room.list` → `room.listing`；或 `room.watch` 订阅 | 0.3 的 `rooms`／`playing` 两栏合成一张表，按 `status` 分 |
| `relay_quickmatch` → `relay_no_room` | 客户端自己用 `room.list` 过滤后挑一间；或者直接排队 | 节点不再单独提供「快速匹配」 |
| `relay_queue` / `relay_queued` | `queue.enter` / `queue.entered` / `queue.match` | 0.3 只有一个池子，现在一张单子可挂多个池子 |
| `relay_find` → `relay_found` | 不需要：`roomId` 里带了节点主机名 | 0.3 多中继时靠它逐台找房 |
| `relay_escrow` / `relay_claim` / `relay_claimed` / `relay_claim_wait` / `relay_claim_refused` / 接管票 | 可选特性 `host-takeover`：`takeover.escrow`、`takeover.claim`、`takeover.granted`、`takeover.wait`、`takeover.refused` | 语义原样搬：托管钥匙、座位凭证指纹、宽限期、选举 |
| `relay_event_report` / `relay_event_results` | `result.report` / `result.confirm`；限制赛战绩板另起 `event.*`（待定） | 0.3 是中继直接记，现在要双方签名 |
| `relay_error` | `error` | 错误码重新编过，见 [01](01-客户端协议.md#错误码) |
| `GET /relays.json`（中继名录） | 节点联邦配置＋客户端内置的节点列表 | |
| `GET /stats.json`（使用统计） | `GET /stats.json` 保留，字段不变 | |
| `GET /latest.json`（更新源） | **不搬进 Tablenet。** 那是独弈自己的发版事务，和联机平台无关 | 独弈官方节点可以继续在同端口答它，但 Tablenet 代码里不出现 |

### 房间元数据字段

| 0.3 | tablenet/1 |
|---|---|
| `gameType`（引擎大类：`constructed`／`commander`／`brawl`／`draft`／`momir`） | 不单独保留，由 `format` 推出 |
| `format`（细分赛制，老客户端为 null） | `format`；为 null 时按 `gameType` 退成 `casual`、`commander`、`brawl`、`draft`、`x-arcane-momir` |
| `mode`（`duel`／`twoHeadedGiant`／`freeForAll`） | `gameType`（`duel`／`2hg`／`ffa`）。注意同名字段含义变了：0.3 的 `gameType` 是引擎大类，tablenet/1 的 `gameType` 是局型 |
| `hostName` | `host.displayName` |
| `hasPassword` | `hasPassword` |
| `matchStructure` | `structure` |
| `visibility` | `visibility` |
| 6 位房号 | `roomId` 的后半段，字母表不变 |

## 老客户端怎么办

独弈 0.3.x 已经装在很多人机器上，不会马上全升级。所以：

1. 官方节点**同时**监听 0.3 的裸 TCP 端口（39231），由节点里的 `legacy-tcp` 网关把 `relay_*` 翻译成 tablenet/1 内部调用。老客户端开的房在新客户端的房间表里也看得见（`venue: "native"`，`codec: "arcane.v0"`）。
2. 新老客户端能不能互打，取决于对局协议本身（独弈的 `protocolVersion` 握手），节点不管。
3. `legacy-tcp` 只放在官方节点的发行配置里，默认关。私服不需要它。
4. 等 0.3 的活跃用户降到很低，再在某个大版本里删掉网关。

## 独弈桌面端要改的地方（0.4）

- 独弈仓库 `crates/arcane-netplay/src/relay.rs`：换成 tablenet/1 客户端（WebSocket＋信封＋通道多路复用），老中继逻辑保留一个版本作回退。
- 对局通道里跑的还是现在的 JSON Lines，所以 `net.rs`、`netmatch.rs`、主机接管、增量帧、zlib 都不用动，只是底下那根管子换了。
- 新增：玩家密钥（生成、导出、导入）、节点列表（官方＋自己加的私服）、外部平台列表和交接确认框、账号绑定入口。
- 中继地址写死在代码里这条规矩照旧：官方节点地址写进 `DEFAULT_NODE`，环境变量只作临时覆盖。

## 从 relay.mjs 能直接搬的

`relay.mjs` 是独弈自己写的代码，用户有权以 MIT 重新发布。可以直接搬进节点的：
- 房号生成和字母表；
- 挂起（`suspended`）和等主机回来的那套「先挂着、到期实话实说」逻辑；
- 主机接管的托管与选举；
- 每 IP 连接数、每房挂起人数这类限流参数；
- `relay.test.mjs` 里的测试场景（改写成新协议）。

节点用什么语言写，见 [待定问题](05-待定问题.md)。
