# 01 · 客户端协议（tablenet/1，草案 0）

本篇是玩家客户端和节点之间说的话。适配器复用同一套信封和握手，只是角色不同（见 [02](02-适配器协议.md)）。

## 传输

- 主通道是 **WebSocket**。公网节点**必须**提供 `wss://`（TLS），局域网和自测**可以**用 `ws://`。
  选 WebSocket 而不沿用现在中继的裸 TCP，是因为浏览器端平台（Endstep 这类）只能讲 WebSocket，而且 443 端口穿得过校园网和公司防火墙。
- 默认路径 `/tablenet/1`，例如 `wss://node.example.org/tablenet/1`。
- 一条 WebSocket 文本帧就是一条 JSON 消息，UTF-8 编码，单条**不得**超过 1 MiB。
- 对局通道里的数据走二进制帧（见 [对局通道](#对局通道)），节点不解析。
- 节点为兼容老客户端**可以**同时监听裸 TCP JSON Lines（见 [04](04-与现有中继的对应.md)）。

## 信封

```json
{ "v": 1, "type": "room.open", "id": "c7", "re": null, "body": { } }
```

| 字段 | 说明 |
|---|---|
| `v` | 信封版本，现在是 `1` |
| `type` | 消息类型，用点分小写：`<域>.<动作>` |
| `id` | 发方给的请求编号，同一连接内不重复。不需要回话的通知可以省略 |
| `re` | 回话里填它回的是哪条请求的 `id` |
| `body` | 正文 |

出错一律回：

```json
{ "type": "error", "re": "c7", "body": { "code": "format_mismatch", "message": "这间房只收 commander", "retryAfterMs": null } }
```

`message` 只是给人看的，客户端判断**必须**看 `code`。错误码见文末。

## 握手与身份

### 密钥

- 每个玩家有一对 **Ed25519** 密钥，客户端第一次启动时生成，存在本机。
- 玩家编号 `playerId` 就是公钥：`ed25519:` 加 base32（小写、无填充）。例如 `ed25519:mfrggzdfmztwq2lknnwg23tpobyxe43uov3ho6dzpi`。
- 名字（`displayName`）是玩家自己填的展示用字符串，可以重名，节点**不得**拿它当身份。
- 节点也有一对自己的密钥，`nodeId` 写法相同。联邦时节点之间靠它认人（见 [03](03-节点联邦.md)）。
- 丢了密钥就是换了一个人。客户端**应当**提供导出／导入。

### 流程

连上后节点先说话：

```json
{ "type": "node.hello", "body": {
  "protocols": ["tablenet/1"],
  "nodeId": "ed25519:...",
  "name": "华东私服",
  "software": { "name": "tablenet-node", "version": "0.1.0" },
  "nonce": "b64:3q2+7w...",
  "features": ["queue", "federation", "p2p.iroh", "legacy-tcp"],
  "limits": { "maxRoomsPerPlayer": 2, "maxMessageBytes": 1048576 },
  "motd": "欢迎"
} }
```

客户端回 `hello`，用私钥签 `"tablenet/1 hello" || nonce || nodeId`：

```json
{ "type": "hello", "id": "c1", "body": {
  "protocol": "tablenet/1",
  "role": "player",
  "playerId": "ed25519:...",
  "sig": "b64:...",
  "displayName": "小明",
  "client": { "name": "duyi", "version": "0.4.0" },
  "venues": ["native"],
  "codecs": ["arcane.v0"],
  "features": ["e2e.noise", "p2p.iroh"],
  "locale": "zh-CN"
} }
```

| 字段 | 说明 |
|---|---|
| `role` | `player`、`adapter`、`node`、`spectator-only` 四选一 |
| `venues` | 这个客户端能去打牌的地方：`native` 表示能当主机也能入座 Tablenet 原生局；其余是外部平台的 `platformId`（玩家自己确认装了／登录了那个平台） |
| `codecs` | 能解的对局编码（见 [对局通道](#对局通道)）。独弈是 `arcane.v0`，对应独弈仓库里的 `packages/protocol-schema/protocol-v0.schema.json` |

节点验签通过回 `welcome`，否则回 `error`（`bad_signature`）并断开：

```json
{ "type": "welcome", "re": "c1", "body": {
  "session": "s_8f2c",
  "resumeToken": "b64:...",
  "you": { "playerId": "ed25519:...", "displayName": "小明", "banned": false },
  "platforms": [ { "platformId": "endstep", "name": "Endstep", "joinKinds": ["handoff"], "online": true } ]
} }
```

`platforms` 是这台节点上当前连着的适配器（见 [02](02-适配器协议.md)），客户端拿它画「可以去哪儿打」。

### 心跳与断线续接

- 双方任一方 30 秒没收到任何帧，就发 `ping`，对方回 `pong`。90 秒没动静即断开。
- 断线后 120 秒内用**同一把密钥**重新握手，节点**必须**恢复这位玩家的排队位置和他开的房间，并在 `welcome.resumed` 里列出接回的房间（`{rooms: [...], queued: bool}`）。身份靠签名认，所以不需要另带续接令牌；`resumeToken` 保留给以后跨节点重启的续接用。
- 同一把密钥在别处又握手成功时，旧连接收到 `error`（`replaced`）后被断开，房间和排队交给新连接。
- 对局里的掉线重连由主机自己管（独弈现有的 1 分钟代让、10 分钟判负），节点只负责把号留着（见 [对局通道](#对局通道)）。

## 赛制与房间

### 赛制标识

赛制用小写短名。核心名单：

`standard` `pioneer` `modern` `premodern` `legacy` `vintage` `pauper` `historic` `timeless`
`commander` `duel-commander` `predh` `pdh` `brawl` `pauper-brawl` `oathbreaker`
`draft` `sealed` `cube` `casual` `casual-commander`

（这份名单取的是独弈 0.3 中继现有赛制的并集，加上 `sealed`、`cube`、`oathbreaker`。独弈特有的 `diy`、`diy-commander` 写成 `x-arcane-diy`、`x-arcane-diy-commander`，因为别的平台不认 DIY 牌。）

外部平台特有的赛制加前缀，例如 `x-endstep-forgetful-fish`。两个赛制名不同就是不同赛制，节点不做「近似匹配」。

### 局型

`gameType`：`duel`（一对一）、`2hg`（双头巨人）、`ffa`（多人混战）、`teams`（组队）、`draft-pod`（轮抓桌）。

### 房间对象

```json
{
  "roomId": "node.example.org/K7Q2MD",
  "venue": "native",
  "title": "来打摩登",
  "host": { "playerId": "ed25519:...", "displayName": "小明" },
  "format": "modern",
  "gameType": "duel",
  "seats": { "total": 2, "taken": 1, "ai": 0 },
  "structure": "bo3",
  "hasPassword": false,
  "visibility": "public",
  "spectate": { "allowed": true, "seeHands": false },
  "status": "waiting",
  "codec": "arcane.v0",
  "createdAt": "2026-11-22T08:00:00Z",
  "join": { "kind": "native" }
}
```

| 字段 | 说明 |
|---|---|
| `roomId` | `<节点主机名>/<房号>`。房号 6 位，字母表 `23456789ABCDEFGHJKMNPQRSTUVWXYZ`（去掉易混的 0/O/1/I/L），沿用现在中继的做法 |
| `venue` | `native` 或某个外部平台的 `platformId` |
| `structure` | `bo1`、`bo3` |
| `visibility` | `public`（进大厅）、`unlisted`（凭号可进）、`private`（只有邀请的人） |
| `status` | `waiting`、`playing`、`suspended`（主机掉线，号还留着） |
| `codec` | 这间房的对局编码，原生房必填；交接房省略 |
| `join` | 怎么入座，见下 |

`join.kind`：
- `native`：走本节点的 [对局通道](#对局通道)。
- `handoff`：要先向适配器要入座链接，见 [02 交接档](02-适配器协议.md#交接档)。
- `bridge`：走对局通道，但另一端是适配器，见 [02 桥接档](02-适配器协议.md#桥接档)。

密码节点不经手：节点只知道 `hasPassword`，密码随入座请求原样转给主机，由主机校验。这和现在的中继一样。

### 消息

| 方向 | `type` | 用途 |
|---|---|---|
| 客→节 | `room.list` | 取房间表，可带过滤 `{venue, format, gameType, status}`，回 `room.listing` |
| 客→节 | `room.watch` / `room.unwatch` | 订阅房间表变动，之后节点推 `room.updated` / `room.removed` |
| 客→节 | `room.open` | 开房（只能开 `native` 房；外部平台的房由适配器发布），回 `room.opened` |
| 客→节 | `room.update` | 改自己房间的标题、空位、可见性 |
| 客→节 | `room.close` | 关房 |
| 客→节 | `room.join` | 入座，带 `{roomId, password?, as: "player"\|"spectator"}`，回 `room.joined` |
| 节→客 | `room.joined` | 原生／桥接：回一个对局通道编号；交接：回入座链接 |

`room.joined` 的两种样子：

```json
{ "type": "room.joined", "re": "c9", "body": { "roomId": "node.example.org/K7Q2MD", "channel": "ch_41", "seat": 1 } }
```

```json
{ "type": "room.joined", "re": "c9", "body": { "roomId": "node.example.org/ES-88213", "handoff": {
  "url": "https://endstep.cc/t/88213?k=...", "code": "88213", "expiresAt": "2026-11-22T08:05:00Z",
  "note": "在 Endstep 网页里打开，需要登录 Endstep 账号"
} } }
```

没有网页入座链接的平台，`handoff` 里给的是 `connect`（服务器地址、房间、密码），格式见 [02 交接档](02-适配器协议.md#有人要入座)。
客户端拿到 `handoff.url` 后**应当**让玩家确认再用系统浏览器打开，**不得**自动打开。

## 排队匹配

### 排队

```json
{ "type": "queue.enter", "id": "c12", "body": {
  "pools": [
    { "format": "modern", "gameType": "duel", "structure": "bo3" },
    { "format": "pioneer", "gameType": "duel", "structure": "bo1" }
  ],
  "venues": ["native", "endstep"],
  "codecs": ["arcane.v0"],
  "rating": null
} }
```

- 一张排队单可以同时挂多个池子，配上任何一个就算配上。
- `venues` 和 `codecs` 可以比 `hello` 里报的少（玩家这次不想去 Endstep 打就不报）。
- 回 `queue.entered`，之后节点每 10 秒推一次 `queue.status`（这个池子里有几人在排、估计还要等多久）。

### 配对规则

两张排队单能配上，要同时满足：
1. 有一个池子的 `format`、`gameType`、`structure` 完全相同；
2. `venues` 的交集不为空；
3. 如果交集里只剩 `native`，`codecs` 的交集也不能为空。

选去哪儿打：交集里有 `native` 就优先 `native`，否则取交集里双方都排在最前面的那个平台。节点**应当**把这条规则写进 `queue.match` 里，让双方看得见。

### 确认

```json
{ "type": "queue.match", "body": {
  "matchId": "m_19c", "pool": { "format": "modern", "gameType": "duel", "structure": "bo3" },
  "venue": "native", "opponents": [ { "playerId": "ed25519:...", "displayName": "阿强" } ],
  "acceptBy": "2026-11-22T08:00:15Z"
} }
```

双方在 15 秒内各回 `queue.accept` 或 `queue.decline`。都接受后：
- `venue` 是 `native`：节点指定一方当主机（先接受的一方），给主机发 `match.host`（带预留的房号），给客人发 `match.join`；
- 是外部平台：节点向那个适配器要开房（见 [02](02-适配器协议.md#按请求开房)），把各自的入座链接通过 `match.handoff` 发给双方。

一方拒绝或超时：拒绝的一方出队，另一方自动回到原排队位置。连续超时 3 次的人，节点**可以**让他冷却 5 分钟再排。

### 匹配分

`rating` 先留空，由节点自己算、自己存，**不得**跨节点互认。是否在 tablenet/1 里规定计分方法，见 [待定问题](05-待定问题.md)。

## 对局通道

原生房和桥接房的对局字节走对局通道。

- 节点给每位入座者和主机之间开一条逻辑通道，编号 `channel`。通道复用同一条 WebSocket：二进制帧开头 4 字节是通道号（大端），其后是负载。
- 节点**不得**解析、改写、缓存或落盘负载。
- 负载的格式由房间的 `codec` 决定。`arcane.v0` 的负载就是独弈现有的 JSON Lines 字节流，所以独弈的对战代码可以不改，和现在过中继一样。
- 主机断线：房间转 `suspended`，号码保留 10 分钟（沿用现在中继的挂起语义）；客人这段时间来入座先挂着，主机回来就接上。
- 主机接管：现在中继里的「托管钥匙＋座位凭证竞选」整体搬过来，作为可选特性 `host-takeover`。消息名改为 `takeover.escrow`、`takeover.claim`，语义不变，细节见 [04](04-与现有中继的对应.md)。

### 端到端加密（可选特性 `e2e.noise`）

现在过中继的对局是明文。tablenet/1 给对局通道加一层可选的端到端加密：
- 双方都声明了 `e2e.noise` 时，通道建立后的头几帧是 Noise `XX` 握手（`Noise_XX_25519_ChaChaPoly_BLAKE2s`），用的是双方的玩家密钥（Ed25519 转 X25519）；
- 握手成功后，负载全部加密，节点只看得到长度和时间；
- 任何一方没声明，就走明文，客户端**应当**在界面上标出来。

### P2P 直连（可选特性 `p2p.iroh`）

双方都声明 `p2p.iroh` 时，可以在对局通道里先交换 iroh 节点地址，打洞成功就把对局挪到直连上，节点那条通道保留作备用。
是否把 iroh 写进 tablenet/1 还是另出扩展规范，见 [待定问题](05-待定问题.md)。

## 观战

- `room.join` 带 `as: "spectator"`。房间 `spectate.allowed` 为假时回 `spectate_disabled`。
- 观战者同样拿一条通道，由主机决定发什么。看不看手牌由主机按 `spectate.seeHands` 执行，节点不管。

## 战绩上报

一局打完，主机发：

```json
{ "type": "result.report", "body": {
  "roomId": "node.example.org/K7Q2MD", "format": "modern", "structure": "bo3",
  "players": [ { "playerId": "ed25519:...", "games": 2 }, { "playerId": "ed25519:...", "games": 1 } ],
  "endedAt": "2026-11-22T08:41:00Z", "reason": "normal"
} }
```

节点把它转给其他入座者，由他们各自用私钥签 `result.confirm`。双方都签了，这条战绩才进本节点的记录。
`reason`：`normal`、`concede`、`timeout`、`disconnect`、`draw`。

## 限流与滥用

节点**应当**至少做：每个 IP 同时在线连接数上限、每人开房数上限（`limits.maxRoomsPerPlayer`）、每秒消息数上限。
超限回 `rate_limited`，带 `retryAfterMs`。拉黑按 `playerId` 记，节点自己管自己的黑名单。

## 错误码

| code | 说明 |
|---|---|
| `unsupported_protocol` | 没有共同的协议版本 |
| `bad_signature` | 握手签名不对 |
| `unknown_type` | 不认识这个消息类型（不断开） |
| `bad_request` | 字段缺失或格式不对 |
| `rate_limited` | 发太快，看 `retryAfterMs` |
| `banned` | 被本节点拉黑 |
| `no_room` | 没有这个房间 |
| `room_full` | 坐满了 |
| `wrong_password` | 密码错（主机回的，节点照转） |
| `format_mismatch` | 赛制或局型不符 |
| `codec_mismatch` | 你解不了这间房的对局编码 |
| `venue_unavailable` | 那个平台的适配器当前不在线 |
| `version_mismatch` | 主机认为客户端版本不兼容（主机回的，节点照转） |
| `spectate_disabled` | 这间房不让观战 |
| `not_owner` | 只有房主能做这件事 |
| `match_expired` | 匹配确认超时 |
| `internal` | 节点自己出错 |
| `not_authenticated` | 还没握手就发了别的消息 |
| `host_offline` | 房主暂时不在（房间挂起中），看 `retryAfterMs` |
| `limit_reached` | 开房数到上限 |
| `replaced` | 同一身份在别处登录，本连接被顶掉 |
| `platform_not_allowed` | 节点没放行这个平台的适配器 |
| `peer_left`／`room_closed` | 对局通道关闭的原因（出现在 `channel.closed.code` 里） |

## 实现时补全的消息（tablenet-node 0.1）

下面这些在上文只提到用途、没写消息名，按参考实现补全。

### 对局通道

| 方向 | `type` | 正文 |
|---|---|---|
| 节→主机 | `channel.opened` | `{channel, roomId, as, password, player: {playerId, displayName}}`：有人入座，主机自己决定收不收、坐哪个位 |
| 双方→节 | `channel.close` | `{channel, code?}`：主机拒人（比如密码错）就带 `code: "wrong_password"` 关掉 |
| 节→对端 | `channel.closed` | `{channel, code}`：另一端关了，或者一端断线（`peer_left`）、房间关了（`room_closed`） |

不是通道两端的连接发来的帧，节点直接丢掉。

### 房间

`room.watch` 回 `room.watching`，`room.unwatch` 回 `room.unwatched`，`room.close` 回 `room.closed`，`room.update` 回 `room.updated`（同一个名字也用于推给订阅者）。
房主掉线时房间转 `suspended`、从大厅撤下（订阅者收到 `room.removed`），房主回来后重新出现。等人阶段的房保留 `resume_seconds`，对局中的房保留 `suspend_minutes`。

### 排队

| 方向 | `type` | 说明 |
|---|---|---|
| 节→客 | `queue.match_cancelled` | `{matchId}`：对方拒绝或超时，你仍在原位置排队 |
| 节→客 | `queue.left` | `{reason, matchId?}`：`left`（自己退）、`declined`、`timeout`。连续超时 3 次冷却 5 分钟 |
| 节→主机 | `match.host` | `{matchId, room, opponents}`：节点已替你开好一间私密房，对手会来入座 |
| 节→客人 | `match.join` | `{matchId, roomId, host}`：去 `room.join` 这间房 |
| 节→客 | `match.handoff` | `{matchId, venue, roomId, handoff}`：配到外部平台，去那边打 |
| 节→客 | `match.bridged` | `{matchId, venue, roomId, channel}`：配到外部平台、走桥接，直接在这条通道上打 |

**第一版排队只支持 `gameType: "duel"`。** 多人局的凑桌规则（几个人、等多久补 AI）还没定。

### 战绩

1. 房主发 `result.report`（正文同上文），回 `result.reported {resultId, reportText}`；
2. 其他在册玩家收到 `result.pending {resultId, reportText}`；
3. **所有在册玩家（含房主）** 各自对 `reportText` 原文签名：`result.confirm {resultId, sig}`，签名内容是 `"tablenet/1 result" || reportText`，回 `result.signed`；
4. 签齐后节点落盘，给每位玩家发 `result.confirmed {resultId}`。一小时没签齐就作废。

`reportText` 由节点生成，带 `resultId`、节点编号、房间、赛制、名次、结束时间、原因、报告人，客户端照原文签，不要自己重新序列化。
