# 08 · 桥接模式：在独弈里打别家服务器上的局（草案 0）

**目标：** 玩家在独弈里坐下、看牌桌、出牌、选目标，但这一局的结算全部由 XMage 或 Hexproof 的服务器做，独弈只负责显示和把玩家的选择传过去。

## 它像什么

**最像独弈现在联机当客人。** 当客人时，独弈本来就不结算：主机的引擎跑规则、发局面、问问题，客人的前端只负责画和答。
桥接模式就是把「主机」换成 XMage 或 Hexproof 的服务器，中间由适配器翻译。

只有一种情况像手动桌：**Hexproof 的手动牌桌模式。** 那种房间服务器本身就不裁决，玩家自己挪牌、横置、放指示物，服务器只负责同步。要在独弈里打这种局，独弈得有一个手动桌界面。

所以分两种：

| 远端类型 | 例子 | 服务器做什么 | 独弈要什么 |
|---|---|---|---|
| **规则型** | XMage；Hexproof 的 Forge 规则房 | 裁决、发局面、问问题 | 现有的客人前端，加一层「远端裁决」开关 |
| **手动型** | Hexproof 手动牌桌房 | 只同步玩家的手动操作 | 新做一个手动桌模式 |

## 翻译放在哪

**放在适配器里（节点那一侧），不放进独弈。** 理由：
1. XMage 只能用 Java 接，而独弈已经不再分发 Java。
2. 翻译放在适配器里，所有独弈客户端共用一份；对方平台升级协议时，只升级适配器，独弈不用发版。
3. 独弈前端只需要认一种编码，不用为每个平台各写一套。

适配器对独弈讲的编码：

| 编码 | 用于 | 内容 |
|---|---|---|
| `arcane.v0`（子集） | 规则型远端 | 独弈现有的对局协议：局面快照＋十一种提问（Priority、DeclareAttackers、DeclareBlockers、PickCards、PickTargets、PickOptions、PickNumber、Arrange、Allocate、NameCard、Mulligan）。适配器把对方的局面和提问翻成这一套 |
| `arcane.manual.v0`（新） | 手动型远端 | 局面快照＋一组自由动作：移区、横置／重置、翻面、加减指示物、造衍生物、改生命、掷骰、洗牌、看牌库顶。没有提问，没有合法性检查 |

握手时适配器在局面里多带一个 `authority`：

```json
{ "authority": { "kind": "remote", "platform": "xmage", "rules": "engine", "features": ["undo:no", "autopay:remote", "stops:remote"] } }
```

独弈前端据此关掉只有本地引擎才有的功能（见 [独弈侧关掉什么](#独弈侧关掉什么)）。

## 规则型：提问怎么对上

独弈的十一种提问是从它自己的引擎里收束出来的，别家引擎的提问种类不同，适配器要逐个映射。

### XMage（2026-11-22 对照 `magefree/mage` master 源码核过）

XMage 服务器问人的地方全在 `HumanPlayer.java`，问法是发一个客户端回调（`ClientCallbackMethod`），然后等玩家用下面五种方式之一回答：

| 回答方式（`MageServer` 接口） | 含义 |
|---|---|
| `sendPlayerUUID(id)` | 点了某个对象：一张牌、一个永久物、一位牌手、一个选项的编号 |
| `sendPlayerBoolean(b)` | 确定／让过／取消 |
| `sendPlayerString(s)` | 特殊按钮（`"special"`，例如「全部进攻」），或者选项的键 |
| `sendPlayerInteger(n)` | 数字；在优先权和宣攻时也当作 F 键快捷让过 |
| `sendPlayerManaType(t)` | 付费时从法术力池里取某种颜色 |
| `sendPlayerAction(a, data)` | 不属于某次提问的动作：让过档位、自动付费开关、撤销、认输等 |

回调到独弈提问的对照：

| XMage 回调 | 触发它的地方 | 独弈提问 | 适配器怎么做 |
|---|---|---|---|
| `GAME_SELECT`，消息是普通优先权 | `priority()` | Priority | 可做的动作取 `GameView.canPlayObjects`（服务器算好的可施放／可起动列表），独弈选了哪个就回那个对象的 `sendPlayerUUID`；让过回 `sendPlayerBoolean` |
| `GAME_SELECT`，消息 `Select attackers`，选项带 `POSSIBLE_ATTACKERS` | `selectAttackers()` | DeclareAttackers | XMage 是一只一只点（每点一只切换一次进不进攻），独弈一次交一组。适配器收到整组后逐只回 `sendPlayerUUID`，有多个防御方时 XMage 还会对每只追问一次 `GAME_TARGET`（攻击谁），适配器照独弈的答案回；最后 `sendPlayerBoolean` 确认。「全部进攻」可以直接回 `sendPlayerString("special")` |
| `GAME_SELECT`，消息 `Select blockers` | `selectBlockers()` | DeclareBlockers | 同上，每个阻挡者点完后 XMage 用 `GAME_TARGET`（`Select attacker to block`）问挡谁 |
| `GAME_TARGET` | `choose()`／`chooseTarget()`，目标在场上或牌手 | PickTargets | 一次只收一个目标，选够了或者回 `sendPlayerBoolean` 结束。独弈的整组答案逐个回 |
| `GAME_TARGET`，带一组牌 | `choose(…Cards…)`，从牌库、坟场等选牌 | PickCards | 同上 |
| `GAME_TARGET`，带分配量 | `chooseTargetAmount()`（分配伤害等） | Allocate | XMage 是选一个目标、再问一次数量，循环到分完；适配器按独弈的分配表逐个回 |
| `GAME_TARGET`，带触发异能 | `chooseTriggeredAbility()` | Arrange | XMage 每次问「哪个先上堆叠」，独弈一次排好全部顺序；适配器按顺序逐个回 |
| `GAME_ASK` | `chooseUse()`；调度 `chooseMulligan()` 也是它 | PickOptions（是／否）；调度时是 Mulligan | 调度的消息文本可以认出来；伦敦调度放底的牌之后会另来一次 `GAME_TARGET` |
| `GAME_CHOOSE_ABILITY` | 选模式 `chooseMode()`、选用哪个异能施放／起动 | PickOptions | |
| `GAME_CHOOSE_CHOICE` | `choose(Choice)`、替代效应排序 `chooseReplacementEffect()` | PickOptions；选项多且可搜索时是 NameCard | 说出牌名在 XMage 里是一个可搜索的 Choice，独弈的 NameCard 面板正好对上 |
| `GAME_CHOOSE_PILE` | `choosePile()` | PickOptions（两堆二选一） | |
| `GAME_GET_AMOUNT` | `getAmount()`、`announceX()` | PickNumber | |
| `GAME_GET_MULTI_AMOUNT` | `getMultiAmount…()` | Allocate | |
| `GAME_PLAY_MANA`／`GAME_PLAY_XMANA` | `playMana()` | Priority 的付费阶段 | 独弈点法术力来源 → `sendPlayerUUID`；点法术力池 → `sendPlayerManaType`；取消 → `sendPlayerBoolean`。也可以打开 XMage 的自动付费（`MANA_AUTO_PAYMENT_ON`） |
| `GAME_UPDATE`／`GAME_UPDATE_AND_INFORM` | 局面变化 | 局面快照 | 把 `GameView` 翻成独弈的局面结构：`players`、`myHand`、`stack`、`exiles`、`revealed`、`lookedAt`、`combat`、`phase`／`step`、`turn` |
| `GAME_INFORM_PERSONAL`／`GAME_ERROR` | 提示、报错 | 信息条 | 原样显示英文 |
| `GAME_OVER`／`END_GAME_INFO` | 一局／一盘结束 | 对局结束 | 同时发 `venue.result` |
| `SIDEBOARD` | 三局两胜换备 | 换备牌墙 | 独弈交回的牌表转成 `DeckCardLists` |

几处要注意：
- **同一个回调对应好几种提问。** `GAME_SELECT` 和 `GAME_TARGET` 都要靠消息文本和 `options` 里的键来分辨。XMage 的消息文本可能随版本改，适配器要把认法集中在一处，认不出就退成通用 PickOptions。
- **XMage 是一问一答、逐个点选，独弈是一次交一组。** 适配器要把独弈的一组答案拆开逐个回，中途 XMage 拒绝了某一个（比如不合法），适配器要把剩下的作废、重新向独弈要一次。
- **提问名对上了，含义不一定一样。** 例如 XMage 的「可以施放」是服务器算的，独弈不能自己再加高亮。

映射不了的提问，适配器**必须**退成一个通用的 PickOptions：把对方给的文字原样当选项，宁可难看也不能卡死。每一次退化都记进适配器日志，按次数排优先级补映射。

### Hexproof 规则房（2026-11-22 对照 `protocol/v3` 和 `rulesengine/forge/prompt*.go` 核过）

Hexproof 规则房底下也是 Forge，提问是**一次交一整组**，和独弈的模型很像，比 XMage 好对得多。

- 局面：`rules.snapshot {turn, step, activeSeat, prioritySeat, players, zones, stack, gameOver, winnerSeat?}`。
- 提问：`rules.prompt {promptId, kind, supported, title, detail, options, choices, cards, targets, combatSources, combatTargets, damage…, min/max…, cancellable}`。
- 回答：`rules.respond {promptId, responseId, cardIds?, targetIds?, assignments?, choiceIds?, orderedIds?, scryPiles?, damageAssignments?, chosenNumber?, name?}`。一次回完，不用逐个点。
- 让过和停点：`rules.priority {fullControl, hold?, stops?}`，可以直接映射独弈的停点设置。

`kind` 一共 20 种（`prompt.go` 里的 `case`）：

| Hexproof `kind` | 独弈提问 | 备注 |
|---|---|---|
| `chooseAction` | Priority | 选项是可施放（`cast`）、可起动（`activateAbility`）、可下地（`playLand`）、撤回法术力（`undoMana`），外加 `$pass`、`$pass-stack`（让到堆叠结算完） |
| `payManaCost` | Priority 的付费阶段 | 点法术力来源；另有 `$pay` 确认、`$auto-pay` 自动付、`$cancel` 取消 |
| `mulligan` | Mulligan | `$keep`／`$mulligan` |
| `mulliganPutBack` | Mulligan（放底） | |
| `chooseAttackers` | DeclareAttackers | `combatSources`×`combatTargets`，用 `assignments` 一次交完 |
| `chooseBlockers` | DeclareBlockers | 同上 |
| `chooseDamageAssignmentOrder` | Arrange | |
| `chooseCombatDamageAssignment` | Allocate | 带 `damageAssignmentMode`（按序／不按序／自由分配）和死触标记 |
| `chooseBoardTargets` | PickTargets | |
| `chooseCards` | PickCards | `minCardSelections`／`maxCardSelections` |
| `reorder` | Arrange | |
| `scry` | Arrange（牌库面板） | `scryDestinations`：牌库顶、牌库底、坟场、放逐、手牌 |
| `chooseBoolean` | PickOptions（是／否） | |
| `chooseColor` | PickOptions | |
| `chooseFromSelection` | PickOptions | |
| `chooseNumber` | PickNumber | |
| `chooseCardName` | NameCard | 回 `name` |
| `revealCards` | 不是提问 | 展示后回 `$ack`。独弈没有「确认已看」这种提问，适配器把牌显示在独弈的展示区，玩家关掉时替他回 `$ack` |
| `acknowledge` | 不是提问 | 同上，显示一条信息 |
| `diceRolled` | 不是提问 | 播掷骰特效，再回 `$ack` |

- **`supported: false`** 是 Hexproof 自己也答不了的提问（它的客户端只显示种类、发不出回答）。适配器照样显示给独弈玩家，并提示「这一步对方平台不支持，只能等超时或认输」，不要假装能答。
- **`autoPassEligible`** 是 hub 给的「这里可以自动让过」提示，独弈可以拿来当智能让过的依据，但最终让不让还是由独弈玩家的停点设置决定（独弈的原则是停点不能因为「手上有瞬间」而变，否则对手看得出你有牌）。**待实测**：它到底看不看手牌。

### Hexproof 手动房

`rulesMode: "manual"` 的房间不裁决，玩家发的是一组 `game.*` 动作，hub 只同步。这一组正好就是 `arcane.manual.v0` 要覆盖的东西：

抽牌、洗牌、调度、弃掉手牌、移牌（单张／多张／牌库里的多张）、横置、翻面、面朝下、改指示物、改阶段、下一回合、下地、展示、搜牌库、重排牌库、改生命和计数器、造衍生物和徽记、统帅税和统帅伤害、箭头和结附、掷骰、抛硬币、随机选、聊天、认输、和局、重开。
另有几种要对手同意的动作（把牌移进公开区、倒出整个区），对应 `game.public_zone_move_requested`／`game.respond_public_zone_move`、`game.zone_dump_requested`／`game.respond_zone_dump`，独弈的手动桌也要能弹「对手请求……，同意吗」。


## 牌怎么认

- 对方给的是牌名，通常还带系列和收藏编号。独弈按名字＋系列在本地牌库里找，找到就用本地的卡图和中文。
- 找不到的（对方有、独弈没有的牌），显示对方给的英文规则文字，配一张白板卡面。
- **规则文字以对方为准。** 本地的中文只是翻译，如果和对方的理解不一样，按对方结算。卡牌详情里**应当**标一句「本局由 XMage 裁决」。

## 独弈侧关掉什么

远端裁决时，依赖本地引擎的功能要关掉，或者换成远端的同类功能。下表的「XMage」一栏已对照源码核过有没有对应功能：

| 功能 | 远端局怎么办 | XMage 有没有对应 |
|---|---|---|
| 自动付费（costs.rs／pay_search.rs） | 关；改用远端的自动付费，或者手动点 | 有：`MANA_AUTO_PAYMENT_ON/OFF`、`MANA_AUTO_PAYMENT_RESTRICTED_ON/OFF`、`USE_FIRST_MANA_ABILITY_ON/OFF` |
| 智能让过、停点 | 映射到远端的跳过设置；远端没有的档位变灰 | 有：`PASS_PRIORITY_UNTIL_*` 七档，加上用户资料里的逐阶段停点（`UserSkipPrioritySteps`） |
| 撤销 | 用远端的 | 有：`UNDO`；回滚回合 `ROLLBACK_TURNS` 要对手同意 |
| 触发排序 | 用远端的自动排序 | 有：`TRIGGER_AUTO_ORDER_*` |
| 手牌减费显示、可施放高亮 | 只信远端给的「可以点哪些」，独弈不自己算 | `GameView.canPlayObjects` |
| 战斗预览（引擎真打） | 关 | 无 |
| 循环捷径 | 关 | 有一个宏重复（`announceRepetitions`），先不接 |
| 对局记录包 `.atrec` | 照录收到的帧，能回放但不能换视角 | — |
| 特效 | 照常，按局面变化触发 | — |

隐私上要特别处理的一项：XMage 允许别人申请看你的手牌（`REQUEST_PERMISSION_TO_SEE_HAND_CARDS`）。适配器**必须**默认拒绝，只有独弈玩家自己点了同意才放行。

## 账号与隐私

- 适配器替每位桥接玩家在对方服务器上保持一个会话。连你自己部署的 XMage 服务器时，适配器可以按 Tablenet 身份自动开账号（例如 `tn-` 加公钥前 8 位）；Hexproof 独立 hub 不用账号。
- **适配器看得到这位玩家能看到的一切，包括他自己的手牌。** 这和对方服务器本身看得到是一样的，但多了一个看得到的人：节点运营者。所以桥接局**不能**做端到端加密，客户端**必须**在入座前提示「这一局经过某某节点的适配器转发」。
- 适配器**不得**把一位玩家的隐藏信息发给另一位玩家的会话。每位玩家一个会话、一条通道，互不相通。

## 独弈要做的事

1. **远端裁决开关**：客人前端读 `authority`，按上表关功能、改提示文字。
2. **提问退化的通用面板**：PickOptions 已经有了，确认它能吃任意长度的英文选项。
3. **牌名找卡**：给远端帧用的「名字＋系列 → 本地卡」查找，找不到出白板。
4. **手动桌模式**（只为手动型远端）：拖牌到任意区、右键菜单（横置、翻面、指示物、衍生物）、生命和骰子。这一块是新界面，工作量最大。
5. **入座流程**：房间表里桥接房的入口、经过适配器的提示、对方平台的服务条款确认。

## 先后

1. 规则型先接 **Hexproof 的 Forge 规则房**：提问一次交一整组，和独弈最像，协议是 JSON，适配器好写好测。
2. 再接 **XMage**：要拆组逐个回、靠文本认提问，适配器只能用 Java。
3. 最后做手动桌，接 Hexproof 手动房。
