# 开放牌桌网络 · 规范初稿（草案 0）

> 状态：**草案**，2026-11-22 起草，供拍板用，未实现。
> 项目名暂用代号 **Tablenet**（协议标识 `tablenet/1`）。正式名别带 “Magic” “MTG”，这两个是威世智的商标。
> 本目录是 Tablenet 仓库的 `spec/`，平台本体以 **MIT** 开源。

## 一句话

一个**不懂规则**的联机网络：负责认人、开房、匹配和转发。一局牌由谁裁决，是各家引擎自己的事。
任何人都能起一个**节点**（私服）。别的对战平台写一个**适配器**接进来，就能和网络里的玩家互相匹配。

## 设计底线

1. **平台不裁决规则。** 节点里不带任何规则引擎，也不带 Forge、Hexproof 或其他 GPL 代码，所以 MIT 不会被传染。
2. **平台不看对局内容。** 对局流量对节点不透明，节点只搬字节；可选端到端加密（见 [协议](01-客户端协议.md#对局通道)）。
3. **适配器是独立进程，按公开协议连节点。** 用什么语言、什么许可证由适配器作者自己定，GPL 的适配器也不会传染平台本体。
4. **接入分三档，门槛从低到高：交接、桥接、原生。** 封闭平台只接交接档也能进网络。
5. **身份是公钥，不是账号。** 换节点、跨节点都认得出是同一个人，不需要中心注册。
6. **战绩和天梯只在本节点内有效。** 对局由主机裁决，主机能作弊，所以跨节点不互认分数。

## 角色

| 角色 | 是什么 | 例子 |
|---|---|---|
| 节点 node | 一台跑 Tablenet 服务端的机器：房间表、排队、中继，可选联邦 | 官方节点、玩家自建私服 |
| 玩家客户端 player | 讲 Tablenet 协议、能自己打牌的客户端 | 独弈桌面版 |
| 适配器 adapter | 替一个外部平台说话的独立进程，节点运营者自己写或平台方写 | 本仓库自带的 XMage、Hexproof 适配器 |
| 主机 host | 某一局的裁决方：跑引擎、发局面 | 独弈开房的那台、Endstep 的服务器 |

## 三档接入

| 档 | 玩家在哪儿打 | 适配器要做的事 | 适合谁 |
|---|---|---|---|
| **交接 handoff** | 对方平台自己的客户端（网页、App） | 发布房间、按请求开房、回一个入座链接或房号 | 封闭平台，例如 Endstep |
| **桥接 bridge** | 讲 Tablenet 的客户端，局面来自对方服务器 | 交接档全部，再加上把对方的局面流转成某种公开编码 | 协议公开的平台，例如 Hexproof |
| **原生 native** | 讲 Tablenet 的客户端，局面来自另一位玩家的主机 | 不需要适配器 | 独弈之间互打 |

**跨平台匹配**的意思是：网络帮两个人找到一个**两人都能去打的地方**，而不是让两个引擎合打一局。
排队时每个人报自己能去哪些平台（`venues`），配对只在交集里找（见 [匹配](01-客户端协议.md#排队匹配)）。

## 约定

- 文中 **必须／不得／应当／可以** 对应 RFC 2119 的 MUST／MUST NOT／SHOULD／MAY。
- 消息例子里省略了公共信封字段，只写 `type` 和 `body`。
- 未知字段**必须**忽略；未知 `type` 回 `error`（`unknown_type`），但**不得**断开连接。
- 扩展字段和自定义值一律加 `x-<厂商>-` 前缀，例如 `x-endstep-richman`。
