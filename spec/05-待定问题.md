# 05 · 待定问题（草案 0）

需要拍板的事，按影响大小排。每条写了初稿里先按什么写的。

## 1. 项目名

初稿用代号 Tablenet。正式名要避开 “Magic” “MTG” “Gathering”，最好也别和现有项目撞名（发布前查一下 GitHub 和 npm、crates.io）。

## 2. 节点用什么语言写

| 选项 | 好处 | 坏处 |
|---|---|---|
| **Rust**（初稿倾向） | 和 `arcane-netplay` 共用代码；单文件可执行、私服部署简单；iroh 是 Rust | 外部平台作者写适配器的门槛略高（但适配器是独立进程，语言随意，不受影响） |
| Node.js | `relay.mjs` 现成可搬；改起来快 | 私服要装 Node；CentOS 7 那种老系统还得找 glibc 2.17 的特制版 |
| Go | 单文件、并发模型简单；Hexproof 服务器也是 Go | 和独弈现有代码共享不了 |

## 3. 主通道用 WebSocket 还是 QUIC

初稿用 WebSocket：浏览器能连、443 能穿防火墙。代价是 TCP 队头阻塞，丢包时对局会卡一下。
可以在 tablenet/1 里只规定 WebSocket，把 QUIC／iroh 当作对局通道的可选升级（初稿就是这么写的）。

## 4. iroh P2P 写进主规范还是另出扩展

初稿把 `p2p.iroh` 写成可选特性。另一种做法是主规范完全不提具体技术，只留「双方可协商把对局通道迁到别的传输上」的口子。
后者更干净，但要等第一个实现出来才知道口子留得对不对。

## 5. 端到端加密是可选还是必选

初稿是可选（`e2e.noise`）。必选更安全，但所有客户端、所有桥接适配器都得实现 Noise，第一版门槛会高很多。
折中：tablenet/1 可选，节点**可以**配置成只收加密房。

## 6. 匹配分要不要统一算法

初稿只留 `rating` 字段，算法由节点自定。统一的话（比如 Glicko-2），不同节点的分数至少口径一致，但仍然不互认。

## 7. 限制赛（轮抓、现开）放不放进 tablenet/1

独弈的轮抓房是「主机管抓牌，抓完各桌复用 1v1 开房」，限制赛战绩板在 0.3 中继里（`relay_event_*`）。
初稿只留了 `gameType: "draft-pod"`，没写抓牌阶段的消息。因为抓牌发生在主机的对局通道里，节点其实不需要懂它；需要节点做的只有「抓完按配对表开 N 间房」和「战绩板」。
倾向：tablenet/1 加一组 `event.*`（开赛事、报配对、报结果、取战绩板），抓牌本身仍归对局编码。

## 8. 外部平台的房间要不要默认跨联邦转发

初稿默认不转（交接链接要本节点的适配器签）。如果某个平台的入座链接本身就是公开的、不需要节点签，转发其实没问题。
可以让适配器在 `venue.room.upsert` 里自己声明 `federatable: true`。

## 9. 先接哪个外部平台

- **Endstep**：闭源，关于页没有公开 API。只能等它的运营方自己按交接档接入。可以在 tablenet/1 定稿后发 issue 或邮件邀请。
- **Hexproof**：GPL-3，协议公开（11 月已是 `hexproof.v3`），它的服务器也是自己可部署的，桥接档和交接档都有可能。同样应当由它的作者来写，或者征得同意。
- **XMage**：MIT（11-22 核过，初稿误写成 GPL-3），服务器自建很普遍，客户端协议是 JBoss Remoting＋Java 序列化，适配器只能用 Java 写。交接档给服务器地址＋桌名＋密码；桥接档的提问对照已核过源码，见 [08](08-桥接模式.md#xmage2026-11-22-对照-magefreemage-master-源码核过)。

**11-22 已定：** XMage 和 Hexproof 的适配器由我们自己写，放在本仓库 `adapters/` 下，XMage 适配器 MIT、Hexproof 适配器 GPL-3.0，节点本体仍是 MIT。Endstep 等它的运营方自己接。
先做哪一个、做到交接档还是桥接档，见 [07](07-首批适配器.md#先后)。

## 10. 许可证细节

平台本体 MIT 已定。还要确认两件事：
- `arcane.v0` 对局协议规范（`protocol-v0.schema.json`）是否也以 MIT 放进 Tablenet 的 `codecs.md`。放进去，别人就能写和独弈互打的客户端；不放，`arcane.v0` 只是一个登记过的名字。
  **桥接模式定了之后这条基本没得选：** XMage、Hexproof 适配器要输出 `arcane.v0`，它们是开源的，等于已经把这套协议公开了。倾向直接把 schema 以 MIT 放进来，新增的 `arcane.manual.v0` 也放这里。
- 参考适配器和一致性测试工具同样 MIT。

## 11. 节点自组网

**11-22 已定**，见 [09 已定](09-节点自组网.md#已定2026-11-22)：名录和协调节点只由项目方运营；根密钥官方持有并备一把备用钥；地区暂不按运营商分；暂不做举报；探测点由名录兼任，海外另起一台。
