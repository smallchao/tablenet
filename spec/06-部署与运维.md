# 06 · 部署与运维（草案 0）

Tablenet 节点是**纯后端**：没有网页、没有管理界面。玩家通过各自的客户端（独弈，或者经适配器接进来的平台）用它，运营者通过配置文件和命令行管它。

## 交付物

| 程序 | 说明 |
|---|---|
| `tablenet-node` | 节点本体，单个可执行文件，Linux x86_64／aarch64 静态链接，另出 Windows 版方便本机自测 |
| `tablenet-adapter-<平台>` | 每个适配器一个程序，单独打包、单独升级 |
| `tablenet-conformance` | 一致性测试工具，适配器作者用 |

另给一份 `Dockerfile` 和一份 `docker-compose.yml`（节点＋可选的 XMage 服务器＋可选的 Hexproof hub＋对应适配器），一条命令就能起一整套私服。

## 配置

一个 TOML 文件，默认 `/etc/tablenet/node.toml`，`--config` 可改。

```toml
[node]
name = "华东私服"
public_host = "node.example.org"      # 写进 roomId 的主机名，必须和证书一致
key_file = "/var/lib/tablenet/node.key"  # 第一次启动自动生成；丢了就换了一台节点
data_dir = "/var/lib/tablenet"

[listen]
ws = "0.0.0.0:443"                     # 或者放在反向代理后面监听 127.0.0.1:8080
tls_cert = "/etc/letsencrypt/live/node.example.org/fullchain.pem"
tls_key  = "/etc/letsencrypt/live/node.example.org/privkey.pem"
legacy_tcp = ""                        # 填 "0.0.0.0:39231" 才开 0.3 兼容网关
admin = "127.0.0.1:7070"               # 管理接口只许监听本机

[limits]
max_connections = 2000
max_connections_per_ip = 8
max_rooms_per_player = 2
messages_per_second = 30
suspend_minutes = 10

[adapters]
# 允许哪些平台接入，以及钉死的公钥（留空表示第一次见到时记下）
xmage    = { key = "ed25519:..." }
hexproof = { key = "" }

[federation]
enabled = false
peers = []
block = []
```

密钥、证书、适配器连别家服务器用的账号密码，一律放文件里，**不得**出现在命令行参数和日志里。

## 管理接口

监听本机的 HTTP 接口，带一个随机令牌（第一次启动写进 `data_dir/admin.token`）。命令行工具 `tablenet-node admin ...` 就是调它：

| 命令 | 作用 |
|---|---|
| `admin status` | 在线人数、房间数、排队人数、各适配器是否在线 |
| `admin rooms` / `admin close <roomId>` | 看房、强制关房 |
| `admin ban <playerId> [--reason]` / `admin unban` | 拉黑 |
| `admin adapters` / `admin adapter-key <platformId> <key>` | 看适配器、换适配器公钥 |
| `admin peers` | 联邦对端状态 |
| `admin reload` | 重读配置（不断开现有连接） |

## 公开的 HTTP

和 WebSocket 同端口：

| 路径 | 内容 |
|---|---|
| `GET /healthz` | `200 ok`，给反向代理和监控用 |
| `GET /node.json` | 节点名、`nodeId`、协议版本、特性、在线的外部平台。客户端添加私服时先读它 |
| `GET /stats.json` | 使用统计，字段沿用独弈 0.3 中继（当天人数、在线人数、历史每天） |
| `GET /metrics` | Prometheus 格式，默认关 |

## 适配器怎么跑

两种都支持：
1. **由节点代管**：在配置里写 `[adapters.xmage] run = "/usr/bin/tablenet-adapter-xmage --config ..."`，节点把它当子进程起，崩了 5 秒后重启，节点退出时一起退出。
2. **自己跑**：适配器作为独立服务，自己连节点的 WebSocket。适配器和节点不在同一台机器时用这种。

无论哪种，适配器和节点之间都是 [02](02-适配器协议.md) 的协议，节点不 import 适配器的代码。

## 存什么

`data_dir` 里只有：节点密钥、黑名单、战绩记录（签过名的 `result.confirm`）、适配器公钥、账号绑定（只有对方平台的公开账号名）。
节点**不**存对局内容、牌表、聊天。备份只需要拷 `data_dir`。

## 日志

写到标准输出，一行一条 JSON，由 systemd 或 Docker 收。日志里**不得**出现密码、令牌、对局负载，`playerId` 只记前 12 位。

## 升级

- 节点重启时，已连接的客户端会断线，靠 `resumeToken` 在 120 秒内续上，排队和房间都还在（`data_dir` 里存了一份续接表）。
- 进行中的对局：主机那条通道断了会转 `suspended`，主机重连回来就接上，和网络抖动一样处理。

## 并入自组网（spec/09）

**运营者：**

```sh
tablenet-node init --config node.toml --region cn-east --public-host 203.0.113.7
# 生成自签证书和配置（名片默认 private）；按提示确认合规后，把 [directory] status 改成 open
tablenet-node run --config node.toml
tablenet-node admin directory --config node.toml   # 看各名录的登记结果
tablenet-node admin drain --config node.toml       # 停机维护前先排空
```

节点要能从公网连上 `listen.ws` 的端口（云主机安全组放行）。`/metrics` 是 Prometheus 格式。

**项目方（名录）：**

1. 在一台不联网的机器上：`tablenet-dir root keygen --out root.key`，再生成一把备用钥 `root-backup.key`。两把公钥写进 `pkg/discovery` 的 `DefaultRoots`（或构建时注入）。
2. 每台名录、每个独立探测点先 `tablenet-dir root keygen` 生成自己的密钥，拿到公钥。
3. 写清单原文 `list.json`（名录的编号、地址、地区；探测点的编号、探测区），离线签名：`tablenet-dir root sign-list --key root.key --in list.json --out directories.json --days 90`。到期前重签。
4. 每台名录：`tablenet-dir init` 写配置，放上自己的密钥和 `directories.json`，`tablenet-dir run`。名录之间每 5 秒互相同步。
5. 海外探测点：`tablenet-probe --dir <香港名录地址> --zone intl --key probe.key`。
6. 认证节点：离线 `tablenet-dir root endorse --key root.key --node <编号> --out endorse.json`，拿到名录上 `tablenet-dir admin endorse endorse.json`。
7. 下架：`tablenet-dir admin delist <编号> [--zones cn] [--reason …]`，撤销用 `undelist`。会同步到别的名录。
